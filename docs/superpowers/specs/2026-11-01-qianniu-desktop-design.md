# 千牛自动回复 Windows 桌面版设计（待确认）

## 目标和依据

为用户制作一款参考所提供“小马过河”截图及匹配说明的千牛自动回复桌面程序。用户确认需要 Windows 桌面版，并说明原软件仅支持千牛 9.1907n。首版以 9.1907n 为兼容目标；能否可靠接入必须实测，不能从原软件的兼容性推断本程序已经可以接入。

附件 XiaoMaII.zip 超出当前工具的 32 MiB 传输上限，未读取、未运行。依据是聊天中的四张截图及文字规则，不依赖原软件代码或服务。

本文件尚待用户确认；当前仅作设计，不代表已经实现。

## 路线选择

1. Windows 本地桌面助手：配合已登录的千牛读取会话、生成并发送回复，符合用户选择。风险是客户端自动化接口的可访问性和版本兼容性必须验证。
2. 官方接口：以授权消息接口完成收发，需要相应平台权限。用户选择桌面版，首版不以获取这些权限为前提；若客户端无法可靠接入，报告事实，再决定是否改用接口路线。

不修改千牛安装文件，不把第三方软件的注册、续费和后台服务作为依赖。

## 实现选择（开发者建议）

- Python 3.12、PySide6 桌面界面、SQLite 本地存储；Windows 打包使用 PyInstaller。
- Windows 10/11 x64 为拟定运行范围；先验证用户实际使用的系统，再宣称兼容其他系统。
- 首版供本地使用，无需注册本程序账号；千牛继续由用户自行登录。
- 使用现有 /workspace/- 检出；本云任务已隔离，不创建额外 Git worktree。
- 规则引擎、存储和回复调度与 Windows 接入层分离，允许在 Linux 上测试核心逻辑。
- Windows 实际打包与千牛联调是独立验收项，Linux 的测试结果不替代它们。

## 功能范围

### 店铺与开关

识别当前已登录且可访问的店铺/客服会话，支持单店启停和全局启停。启动默认暂停；用户开启后才自动发送。明确展示连接、暂停、版本不匹配、无法识别会话、发送失败等状态。

先验证单店铺单会话收发，再验证多个会话及多店铺隔离；未通过后者时不得宣称支持多店铺自动回复。

### 话术管理与测试

支持规则新增、编辑、删除、分类、收藏、启用/禁用、优先级、搜索、本地 JSON 导入导出。每条规则包含标识、名称、适用店铺或通用范围、分类、匹配类型、条件、多个回复内容、优先级及启用状态。

测试页输入买家消息，展示归一化文本、命中规则、命中条件组和回复预览。测试不连接千牛、不发送消息，且不消耗正式会话的轮播进度。AI 测试显式触发并提示会调用用户配置的接口。

首版建议按较小优先级数字优先，同值时店铺专用规则优先于通用规则，再按创建顺序选择；这是开发者建议，非已确认的原软件行为。每条消息只采用第一条命中的普通规则。

规则多个回复用 # 分隔、按顺序循环；高级编辑器也提供逐项输入，回复中的字面 # 可通过逐项输入保留。正式轮播状态按店铺、规则保存，在确认发送成功后推进；失败和预览不推进。

未命中策略可选“不回复 / 固定默认回复 / AI”，三者明确互斥。AI 服务支持 OpenAI GPT 和 DeepSeek，每次只使用用户选定的一家，不同时调用或自动切换到另一家；用户补充希望接入 GPT，OpenAI GPT 作为优先实现的服务。另提供最简模式，开启后所有受支持的买家文本消息使用统一话术，不再进入普通规则。

### 匹配语法（需确认的解释）

原说明的“包含所有关键词”与问候词示例不一致；关于多层 | 的表述也有冲突。本设计建议以能解释主要示例的以下语法为准，并在编辑器中显示解释，拒绝无法解释的输入，不静默猜测。

- #：完整条件之间的“或”，例如 你好#您好，任意一项包含即命中。显示时可用逗号分隔标签，但存储、编辑仍保留 #，不把用户输入的普通逗号自动变成逻辑运算符。
- |：同组词之间的“或”，例如 发|可|能。
- +：组之间的“且”，顺序不限，例如 发|可|能+邮政。
- &：前后词组须依次出现，例如 不要|别发&中通|圆通。
- 运算优先级从高到低为 |、&、+、#；完整复杂条件的“或”统一用 # 表示。例：你好|您好+在吗|在么，解释为（你好或您好）且（在吗或在么）。
- 暂不支持括号或减号运算；- 在条件中报错，+、|、&、# 只能作运算符，不能作为单个词的字面内容。空条件、空词组、连续运算符报错。
- 顺序匹配要求选择的各词段在归一化消息中依次出现且不重叠，允许段之间有其他字；算法必须考虑同词多次出现的情况。
- 完全匹配只接受 # 分隔的候选句，归一化后逐句判断相等，不把 +、|、& 解释成完全匹配表达式。
- 归一化对买家消息和条件中的词采取相同处理：移除 Unicode 标点和用户说明列出的其他符号（含 ×、$、~、+、=、| 等）；保留文字、数字、空白和大小写，不擅自扩展为同义词或模糊匹配。解析运算符先于词内容归一化；归一化后空词、空消息不匹配。

验收例：

| 条件 / 类型 | 消息 | 结果 |
| --- | --- | --- |
| 你好#您好 / 包含 | 您好，在么？ | 命中 |
| 你好#您好 / 包含 | 客服好，帮我退下款 | 不命中 |
| 你好|您好+在吗|在么 / 包含 | 在么，你好？ | 命中 |
| 你好|您好+在吗|在么+东西|商品 / 包含 | 您好，在么？ | 不命中（缺少第三组） |
| 发|可|能+邮政 / 包含 | 可不可以发邮政？ | 命中 |
| 发|可|能+邮政 / 包含 | 能给我发下中通 | 不命中 |
| 不要|别发&中通|圆通 / 包含 | 不要发中通 | 命中 |
| 不要|别发&中通|圆通 / 包含 | 中通不要发 | 不命中 |
| 为什么物流不更新#怎么还没到？ / 完全 | 怎么还没到 | 命中 |
| 为什么物流不更新#怎么还没到？ / 完全 | 怎么还没有到 | 不命中 |

原文中第三组“东西|商品”却仍称“您好，在么？”匹配成功的例子按上述解释属于文档错误；这是待用户确认的行为差异，不宣称百分之百兼容原软件。

### 千牛接入与回复调度

第一阶段在用户 Windows 上用可单独运行的诊断工具检查版本标识、进程和窗口、Windows UI Automation 可访问的控件、店铺/会话标识和消息事件。工具默认只读、输出结构及能力状态，不默认导出聊天正文。

优先使用可访问性接口和控件级操作。不能先承诺 9.1907n 会暴露这些信息；如果关键消息或身份信息不可访问，自动收发暂停在此阶段，报告缺失能力，不能用模拟消息冒充接入成功。OCR/坐标点击不作为首版可靠自动回复的默认实现。

接入需提供明确的店铺和会话标识、消息方向、事件身份及消息内容。仅处理开始监听后出现的买家新文本，不回复历史消息、客服本人消息或系统提示。图片/表情识别、图片 OCR、订单自动处理留作后续能力；遇到这些消息默认不自动回复，也不按普通空文本触发兜底。

每店铺串行发送，跨店铺会话独立排队。发送前重新确认全局/店铺开关、目标会话、消息是否仍待处理和是否发生人工接管。切错会话、身份不明、规则变更或人工接管时取消旧待发任务；人工接管后须明确恢复自动回复。

每个消息事件至多自动回复一次；不可仅用“消息内容相同”去重，以免吞掉买家重复提问。必须验证能取得稳定事件身份，或可经测试保证稳定的会话内事件序号。断线重连不回放旧消息，重启后从新监听基线开始。

以下交互为开发者建议，随本设计一并确认：人工点击“接管”或检测到非本程序发出的客服消息后，暂停该会话，不暂停整店；仅切换会话不等于人工接管。目标输入框非空时禁止自动输入或发送，避免覆盖人工草稿；诊断阶段必须验证能读取该状态并区分本程序出站消息与人工消息。

普通规则按每条买家消息独立匹配，不自动拼接后匹配。同一会话买家在 AI 等待期间追加消息时，旧 AI 任务失效，先匹配新增消息的规则；若新增消息仍须 AI 回复，以该轮尚未答复的买家消息作为当前问题重新生成，只发送最新有效答案。该轮上下文限最近 10 条且总计 4000 字，超过时截取最近内容；不附带更早历史。AI 请求在最后一次新消息后静默 1 秒再发起，并且每会话最多一个有效请求，避免逐字追加触发重复调用。上述时长、条数和字数为可调整的实现默认值。

发送成功需观察目标会话中对应的新增客服出站消息；只点击发送按钮不算成功。若无法确认结果，记录“结果未确认”，暂停该会话且不自动重试，避免重复发送。测试发送只在用户选择的测试会话内进行。

### OpenAI GPT、DeepSeek 与本地数据

AI 可选，默认关闭。用户补充提出连接 GPT，使用 OpenAI 官方 API 接入；保留截图中的 DeepSeek 为可选服务。允许配置用户自己的对应服务 API Key、可用模型标识和店铺基础信息；默认推荐服务为 OpenAI，不猜测用户账号可用的具体模型。通过统一服务接口复用超时、错误处理和回复失效逻辑，各服务分别适配并测试。ChatGPT 会员与 API 用量独立，不把 ChatGPT 网页登录或会员订阅当作 API 凭据；不实现原软件的卡密、充值次数与计费后台。

GPT 按配置的商品、发货和售后资料回答；资料不明确的价格、库存、物流时效等不自行编造，也不代替人工承诺退款或订单操作。无足够依据时使用用户设置的转人工话术。

API Key 在应用设置中输入，按服务分别放入 Windows 凭据管理器，数据库只存引用；不在聊天中索取密钥，不写进仓库、导出文件或日志。只向当前选定服务发送当前问题（含该轮尚未答复的有限追加消息）及用户配置的必要店铺信息，首版不上传整段聊天历史。

AI 请求超时、断网、无可用凭据时记录原因并不发送 AI 回复；不把错误信息发给买家，也不反复请求。等待期间发生人工回复、会话暂停或规则变化时，丢弃过时答案。

规则和运行历史存于当前 Windows 用户的应用数据目录。历史记录消息事件标识、店铺、会话、命中规则、回复、状态及时间；默认只留最近 30 天，界面提供清除及关闭正文记录选项。导出规则不包含聊天历史或凭据。首次运行不载入截图里的真实商店名称、账号或话术作为用户数据。

## 首版不包含

原软件账号系统、收费和卡密后台、对其他千牛版本的兼容承诺、图片理解、订单操作、自动登录千牛、未经实测的多店铺收发支持。界面可参考截图的功能分区，使用独立程序名称和图标。

## 交付与验收边界

1. 核心代码与自动测试：覆盖上表、复杂规则解析错误、符号归一化、顺序/重复词、优先级、禁用、轮播、店铺隔离、人工接管、去重、失败和过时 AI 回复；分别模拟并验证 GPT/DeepSeek 服务的正常回复、超时、认证失败、限流和空回复。模拟服务通过不代表真实 API 已验证；真实连通需使用用户已配置的对应凭据单独测试。
2. 桌面话术管理、测试和历史功能；用模拟接入时清楚标注“模拟”，不得显示真实千牛已连接。
3. Windows 诊断工具和操作说明。用户机器上的检查结果决定千牛适配能否继续；当前 Linux 无法完成此验收。
4. 适配可行后，逐项在千牛 9.1907n 测试：单会话收发、多个会话不串发、人工接管、重复事件、断线重连及开关；多店铺作为独立门槛。
5. 在 Windows 构建可执行程序，并在无开发工具的 Windows 环境启动验证。未执行时明确标为未验证，不用源码包冒充可用 exe。
