# Windows 实机验收清单

当前外部前提：需要一台运行千牛 9.1907n 的 Windows 电脑。云端是 Linux，无千牛安装、会话或聊天控件，不能替代此验收。不需要用户提供账号密码。

## 1. 桌面和固定文字回复

- [ ] 记录 Windows 版本、64 位架构、内存及可选显卡信息。
- [ ] 源码启动或 Windows 打包程序启动成功；首次打开真实发送关闭。
- [ ] 新增/编辑/分类/禁用/收藏/导入/导出、关闭重开后规则保留。
以下两项仅适用于用户选择启用可选本地 AI；固定文字回复无需执行。

- [ ] Ollama 已启动，本地模型已安装，检测和真实试答成功。当前开发机仅验证客户端协议与受控服务，未验证用户模型生成。
- [ ] 断开网络后，本地模型仍可回复；停掉 Ollama 后程序显示错误，不产生虚假成功记录。

## 2. 只读千牛诊断（下一步所需）

- [ ] 千牛帮助/关于界面确认为 9.1907n；记录报告中的 ProductVersion/FileVersion，不能仅按安装包名判定。
- [ ] 运行只读检测，检查目标进程和控件树。如果 UIA 不暴露必要字段，先记录缺失能力；不要启用自动发送。
- [ ] 证明能区分店铺、客服、买家会话与消息方向；验证新消息事件身份稳定。
- [ ] 证明启动/断线重连不会把旧消息当成新消息。
- [ ] 证明可以检测目标输入框已有人工草稿，且不会覆盖。

目前没有实际控件映射或经过验证的 live adapter。需据上述报告实现，再继续下面的收发验收；界面、规则引擎、模拟器通过不能替代此步骤。

## 3. 明确选择的测试会话内收发

- [ ] 发送前二次确认店铺和会话；发送后观察该会话的新增客服消息作为确认。
- [ ] 对买家重复发送的同一句，按不同事件分别处理；同一事件重报不重复回复。
- [ ] 轮播仅在确认后推进；无法确认结果时暂停该会话，不自动重发。
- [ ] 人工发送或点击接管，立即取消该会话待发回复；须手动恢复。
- [ ] GPT/收费 API 不存在于自用版配置，AI 请求只到本机 Ollama。
- [ ] 本地 AI 等待期间收到补充消息、改规则或暂停，旧回复不发出。
- [ ] 单店多会话与多店铺分别验收；未通过多店铺前不得宣称支持。
- [ ] 逐店资料隔离后再开启多店铺 AI，禁止用通用资料冒充店铺专用知识。

## 4. 独立 Windows 分发验证

- [ ] `build_windows.ps1` 全部通过，打包的诊断入口输出 UTF-8 JSON。
- [ ] 在无 Python/开发工具的 Windows 机器解压整个文件夹，exe 能打开，字体和 DPI 正常。
- [ ] 保存/导出、模型检测、取消任务、正常退出、重开均通过。
- [ ] 分发包不包含本地数据库、聊天报告或用户资料。
