# 聊天区域检测 v3

第二份实机报告已找到 Chrome/CEF Document、Text、Group 等网页控件，且 FileVersionNumeric 为 9.19.7.0。检测没有接口错误记录，但树在深度 6 停止，且许多隐藏窗口消耗了 20 窗口额度。当前还没有已确认的买家消息区、会话标识、聊天编辑器或发送按钮。

## 本次针对性调整

- 先检查可见且未最小化的窗口，避免隐藏工具窗口挤掉实际聊天窗口；隐藏窗口不再枚举内部结构。
- 直接以可见的 Chrome_RenderWidgetHostHWND 为根，按区域面积优先检查。每窗口最多选择 4 个、全局最多探测 6 个渲染器根。
- 网页树深度增加到 32，每个根最多 1200 个节点，并带相对路径；每个根约 5 秒、整个扫描约 18 秒、父进程监督 25 秒。底层调用阻塞时保留部分报告。
- 先查询 Edit 和 Button 类型候选，再遍历长聊天记录；先保存候选进度，避免后续树读取卡住而丢失已取得信息。
- 记录控件运行期标识、所属进程、矩形和辅助功能模式。默认不读取名称，更不读取 Value/Text 内容，不执行点击、输入或发送。
- 候选中排除密码输入和屏幕外控件。名称采集仍由已有的显式选项控制，密码控件不采集名称。
- 独立父进程接受 v2/v3 报告，文件限额调整至 20 MB，以容纳较深结构；v3 的 `report_version` 为 3。

控件 path、runtime_id 和类似数字的 AutomationId 都只是观察标识，尚不能作为稳定的买家消息或会话 ID。类型为 Edit 的控件可能是搜索框，Button 也可能是导航按钮；必须进一步确认用途，不能据此自动发送。

## Windows 下一步

1. 从 GitHub 下载本次最新版本，解压到新文件夹。
2. 打开千牛“客服接待”，进入一个买家聊天，保持窗口可见；关闭关于等弹窗。
3. 双击根目录 `检测千牛.bat`，按提示运行。
4. 上传新的 `reports/qianniu-diagnostic.json`；开头应有 `"report_version": 3`。

不需要安装模型、配置 AI 或重新安装 Python。此工具仍为只读定位；实际消息接收和自动发送尚未验收。
